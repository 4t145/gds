# GDS 设置中心 · 原生实现规则

本文基于 0.3 概念设计，并以本页的原生修订为准，集中定义设置中心的导航、页面组织和当前应用作用域；不是 Files 专属外观页，也不是运行时插件系统。历史 HTML / PNG 保留示意，不代表当前入口或保存方式。当前实现范围见 [开发与运行说明](../development.md)。

## 1. 入口与页面布局

主页面左上菜单中的设置项或 `Ctrl+,` 打开 / 聚焦**完整设置中心**，底部不再设置独立入口。外观和快捷键都只是其中一页，不能把全局入口改成某个专用页面。默认绑定及按钮提示统一遵循 [快捷键与键帽](../vistual-language/shortcuts.md)。

设置中心沿用 [公共窗口框架](../vistual-language/README.md)，替换工作区呈现；左上菜单位置改为 ArrowLeft 返回文件浏览，不在右上放 X 返回。最近、收藏等次级页采用同一返回位置。主体采用左侧分类导航、右侧页面内容，各页共用标题、作用域标识和表单布局。

分类条目复用公共 NavItem：38 px 点击区、18 px 图标、10 px 侧栏内边距；展开时左对齐，折叠时图标居中且尺寸不变。设置根容器透明，左栏只绘制侧栏背景、右页单独绘制内容背景；左列从顶栏到侧栏及底部留白保持同一材质，不叠加内容底色。状态反馈位于右侧页内容内，没有保存按钮或额外全宽底栏。

进入设置只切换呈现，不销毁原工作区。返回后恢复原文件标签、路径、选择、滚动位置，以及终端的会话集合、活动会话、dock 显隐和大小；正在运行的会话不因打开设置而结束。

设置中心不是一个可关闭的文件标签。使用 `Esc` 或返回入口退出；局部编辑 / 临时浮层先处理自身取消，不让页签快捷键在设置背后新建或关闭文件标签。具体分发顺序见 [快捷键焦点契约](../vistual-language/shortcuts.md#4-焦点与-scope-契约)。

在设置界面内，`Ctrl+Tab` / `Ctrl+Shift+Tab` 按左侧导航顺序循环切换页面，首末相连；只改变当前可见页，不修改文件标签或任何偏好值，离开的页面上未确认的下拉菜单随焦点转移关闭。焦点在模态弹窗内时按键不切换页面。按住 `Ctrl` 时，侧栏中相对当前页的“下一项 / 上一项”在行尾分别显示 `Tab` / `Shift+Tab`，省略已按住的 Ctrl；不伪造逐页直达快捷键。

## 2. 导航与作用域

| 页面 | 内容范围 | 设置作用域 |
| --- | --- | --- |
| 常规 | 语言、时间显示格式与通用交互偏好 | 仅当前应用（Files） |
| 外观 | 主题来源与明暗、字体与密度、图标、透明度 / 模糊、可读性 | 仅当前应用；来源映射与能力边界见 [共享主题](../vistual-language/theme.md) |
| 终端 | shell、启动参数 / login 偏好、终端字体与 ANSI 配色等终端偏好 | 仅当前应用；具体运行会话仍归所属工作上下文 |
| 快捷键 | 当前应用动作的绑定 | 仅当前应用，不能无提示改动别的应用 |
| 当前应用 → 文件浏览 | 默认视图、打开方式、隐藏文件、标签恢复等文件浏览偏好 | 仅 Files，不改变其他应用 |

每页统一标出“当前应用”，不依赖用户从路径猜测作用域。公共层承载窗口框架、导航、设置行、滑块及主题／字体等基础偏好模型；页面目录和应用偏好模型由应用持有。配置文件也各自独立：本轮每个应用只读写自己的配置，不提供“全局 / 本应用”切换，也不同步其他应用的设置。外观变更只影响当前应用，且不意味着修改 Qt / DMS 源文件或桌面本身；跨应用统一设置留待以后单独设计。

应用分组使用相同页面与表单组件，只展示当前应用支持的偏好。文件复制、删除、目录导航、真实终端会话操作不是设置页的职责。

“快捷键”页读取当前应用的动作表和套件基础动作，展示动作名、**有效绑定**及 scope；绑定列与菜单右列 / 按钮 tooltip 使用同一个 ShortcutBadge，统一对齐、保持组合不拆行，未绑定时明确写“未绑定”。未来重映射应同步更新四个消费者，而不是只改设置页的文字。本轮只演示绑定展示与作用域，不实现完整重映射编辑器或插件系统；默认表与显示细则集中在 [快捷键与键帽](../vistual-language/shortcuts.md)，此页不再维护第二份表。

### 公共设置控件与默认值

配置类型可通过 `#[derive(gds::ConfigEditor)]` 与 `#[setting(...)]` 派生公共原生表单，已用于 Files 的语言、时间格式和字体设置；类型映射、标注及应用/保存接线见 [配置编辑器宏](config-editor.md)。

- 语言、时间显示、主题、明暗等枚举值使用下拉框，不因当前只有几个选项而排成一行按钮。语言下拉支持搜索，当前只注册已经提供翻译的语言；新增语言扩展选项目录即可。
- 时间显示默认为“相对时间”，可切换为“完整日期时间”；修改 `time_format` 后立即生效并保存，恢复此字段不改变语言、主题、文件列配置或隐藏文件偏好。
- 字体使用可搜索下拉框，选项来自平台文本系统已安装的字体（`gpui::TextSystem::all_font_names`），首项“跟随系统”恢复系统 / Kit 默认字体；已保存但当前未安装的字体会以“未安装”标记显示，运行时回退到系统字体，绝不改写已保存的选择。所选字体缺少中文字形时由 GPUI 的字体回退链逐字补齐，不整段替换字体。字号使用同一数值滑块，范围 12–24 px、默认 16 px（与改动前的视觉一致）。
- 字体与字号都是当前应用的偏好：两者各自恢复默认，并立即应用、保存；切换主题来源、明暗或不透明度不会重置它们。字号改变会刷新窗口，但不改变文件数据、选择、标签或列配置。显式像素文字通过 `typography::scaled` 跟随同一基准，`rem` 文字随 Kit 的主题基准自动变化。
- 每个应用的外观设置都提供“主界面背景不透明度”和“侧边栏背景不透明度”，默认分别为 85% 和 50%，通过公共百分比滑块独立调整、即时生效并保存到当前应用配置。每项有独立的恢复默认操作，只影响背景，文字和图标保持不透明。
- 语言切换后，字体控件中的“跟随系统”“未安装”等文案与示例文字也随同一翻译资源更新；字体控件与其他下拉共用 `SettingRow` 的恢复默认按钮。
- 百分比及后续数值设置共用带当前值显示的滑块，范围和步长由字段定义，不再使用加减按钮代替滑动操作。
- 所有可编辑字段以 `Preferences::default()` 为默认基线。当前值偏离该字段默认值时，在右侧控件组左边显示小型恢复按钮；默认状态保留相同空位，避免控件跳动。恢复仅改变该字段，并立即应用、保存。
- 数值的变更和默认比较采用组件步进精度，避免旧浮点运算结果（例如 `0.6999999`）被误判成新的修改。程序反向同步不发出修改事件。
- **主题与明暗的默认值都是“跟随系统”。** 主题下拉中系统与内置平级；明暗下拉提供跟随系统 / 浅色 / 深色，手动选择始终覆盖系统明暗。当前 Niri 系统配色及活动模式由 DMS 导出提供，内置主题的系统模式使用平台明暗偏好。
- 主题 / 明暗恢复默认只将对应字段还原为跟随系统，不改写其他字段。已有明确保存的内置主题、浅色或深色选择不会被升级过程覆盖。Qt 适配代码和已有配置保留，但 Qt 不出现在可选主题列表。

### 即时应用与错误反馈

- 每次真实偏好变化立即发出一次 `Event::Apply` 并自动保存，不等待保存按钮或长时间防抖；同值选择、步进到边界后未变化的操作不重复请求。
- 只有实际变化的外观 / 语言需要重新应用，修改文件偏好不触发无关主题源读取。
- 应用失败恢复上一次有效偏好并显示错误；写盘失败保留已生效的运行态，明确提示“已生效但未保存”，不伪报成功。
- 偏好保存在当前应用自己的配置文件中（Files 为 `$XDG_CONFIG_HOME/gds/files/settings.toml`）。首次以本应用配置启动时，若该文件尚不存在，会只读导入旧套件配置 `gds/settings.toml` 并原子复制到新路径；此后只写新路径，旧文件绝不覆盖或删除。新配置已存在时优先使用新配置；旧配置损坏时报错而不是写入默认值；复制失败时保留已读取的旧偏好用于本次运行并明确提示，下次启动重试。并发创建的新配置不会被导入覆盖。声明式符号链接或只读的新目标仍按原有规则拒绝写入。
- `set_preferences` 等程序回写只更新呈现，不再发出应用事件，避免循环；错误通过共享通知气泡报告。退出设置仅返回工作区，不是提交或撤销已经生效的修改。

## 3. 页面集中组织

每个应用的偏好页集中在自己的设置目录。套件公共部分只保留所有应用采用的呈现与基础规则：

```text
src/ui/settings.rs                  设置行、数值范围、滑块与键盘步进
src/ui/settings/form/               类型化配置编辑器、校验与字段状态
crates/gds-settings-derive/          配置类型与 UI 标注的派生宏
src/typography.rs                   字体与基准字号
src/theme.rs + theme/               主题来源、语义配色和材质
src/bin/files/settings.rs            Files 设置中心与偏好模型
src/bin/files/settings/pages/        Files 的常规、外观、终端、快捷键和文件页
src/bin/files/settings/controls.rs   Files 字段与公共控件之间的映射
src/bin/files/settings/storage.rs    Files 配置读取、旧配置导入和保存
src/bin/agents/settings.rs           Agents 设置中心与导航
src/bin/agents/settings/             Agents 外观、会话、连接和服务管理表单
```

Files 的列布局、标签／卷侧栏偏好和配置路径属于 Files，不进入公共偏好结构；卷发现和操作也保留在 `src/bin/files/storage`。Agents 的客户端协议、配置文档、认证、安装器和会话状态仍属于 Agents。公共 `SettingRow` 和 `NumberControl` 不认识这些领域模型，也不负责写盘。

共享的是基础设计语言与服务，不要求两种应用拥有同一份页面枚举、配置 schema 或保存实现。两者均以 ArrowLeft 返回仍存活的工作区，使用统一 NavItem 与设置行；只有没有工作区的设置专用启动才建立独立宿主。Files 继续使用原布局和配置文件。Agents 的本机偏好标为当前应用，服务管理页明确显示当前服务地址，不能把远端服务写操作伪装成本机界面设置。

- 用户偏好页面不散落到主题模块、会话模块或公共协议层中。
- 不为页面注册建立动态插件、通用表单语言或设置服务框架。
- 窗口、文件标签、会话草稿和正在运行的任务不是设置页可以重建的数据。

## 4. 原生修订与验收边界

0.3 HTML / PNG 只保留历史交互示意，其中的底部设置入口、右上返回 X 或保存流程不再适用于原生 App。本页描述当前规则，不代表已经通过完整原生显示或输入验收；验证状态见 [运行说明](../development.md)。

验收重点：

1. 主页面菜单或 `Ctrl+,` 到达完整设置中心；设置、最近与收藏使用左上 ArrowLeft 返回文件浏览。
2. 分类条目使用统一 NavItem，展开 / 折叠同高；每页作用域在修改前可见，均标为当前应用。
3. 整条左列材质连续，只绘制一次侧栏背景；右内容独立绘制，没有保存底栏或底部设置入口。
4. 真实修改即时应用，同值不重复写；失败反馈与程序回写不引发循环，返回工作区保留上下文。
5. 外观页连接共享主题代码，但设置只写入当前应用；设置中心本身不依赖 Files 二进制代码。
6. 快捷键页、菜单与按钮提示显示同一有效绑定；作用域清楚，键帽对齐，未绑定项不伪造按键。视觉 / 焦点规则见 [快捷键与键帽](../vistual-language/shortcuts.md)。
7. `Ctrl+Tab` / `Ctrl+Shift+Tab` 在设置页间循环且不改变文件标签或偏好；离开的页不留下悬挂菜单，弹窗打开时不切页；按住 `Ctrl` 时相邻导航项在行尾显示 `Tab` / `Shift+Tab`；Ctrl 与 Alt 提示分别过滤自己的组合，不显示另一组。
8. 首次启动只读导入旧套件配置后，只在新应用路径写入；旧文件保持不变，后续修改不再读取旧文件。
